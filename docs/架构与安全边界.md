# 架构与安全边界

## 四层结构

1. 平台适配与目录发现：把 Codex、Claude、WorkBuddy 和自定义项目目录映射为统一 `SkillRoot` 与 `SkillInstallation`，同时保留宿主、作用域、来源和专属元数据。
2. 索引分析：后台扫描 `SKILL.md` 和静态文件清单，解析 YAML，执行本地规则与重复项分析，并把缓存写入 SQLite。原文件仍是唯一内容源。
3. 安全操作：所有写入都检查来源、规范化路径、真实路径、符号链接边界和预期哈希；修改前建立快照，改名/回收/恢复写入操作日志。
4. Electron 界面：React 渲染进程不接触 Node.js 或文件系统，只调用 preload 暴露的窄接口。

## 进程与 IPC

- 渲染进程启用 `sandbox` 与 `contextIsolation`，关闭 `nodeIntegration`，拒绝权限请求和页面外导航。
- Forge fuses 禁用 `RunAsNode`、`NODE_OPTIONS` 和调试参数，启用 Cookie 加密与 ASAR 完整性约束。
- IPC 输入统一经 Zod 校验。文件接口接收 Skill ID 和相对路径，不接受任意目标文件路径。
- Markdown 经过白名单清洗；外部链接只允许由主进程交给系统浏览器打开。

## 文件修改规则

- 只有用户或项目来源、且根目录标记可写的 Skill 才能修改。
- `SKILL.md` 解析保留 BOM、LF/CRLF、未知 YAML 字段与注释；保存前展示差异。
- 写入前比较加载时哈希与磁盘当前哈希，外部修改会进入冲突流程。
- 原子保存使用 Skill 文件同目录临时文件；改名在执行前检查目标目录、已知宿主元数据和自引用。
- 删除只会移动到工作台 `trash`。跨盘移动采用复制、哈希验证后再删除源目录；应用不提供永久清空操作。

## AI 数据流

本地规则不联网。用户主动运行 AI 时，界面先显示主文件、候选附件、字节数和排除原因。附件文本单项最多 200 KB，脚本和二进制始终排除。结果通过 Zod 校验后按内容哈希、服务、模型和提示版本缓存；Skill 内容变化后旧结果保留但标记过期。

密钥使用 Electron `safeStorage` 加密。Windows 打包环境下由系统用户上下文保护；数据库、日志、导出和渲染层均不保存或回传明文。

## 数据模型

SQLite 保存根目录、Skill 索引、分类标签、快照、操作日志、AI 服务和分析缓存。内容修改始终落回原 Skill 文件，数据库中的正文仅用于搜索和冷启动缓存；重新扫描会以磁盘内容为准。
