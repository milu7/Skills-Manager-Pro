# 数据备份与恢复

Skill 管理工作台不会把现有 Skill 迁入中央仓库，所以备份分成两部分：原 Skill 目录，以及工作台自己的索引与历史。

## 备份

1. 退出工作台，确认任务管理器中没有 `SkillsManagerPro.exe`。
2. 备份你实际使用的 Skill 目录，例如 `.codex\skills`、`.claude\skills`、`.workbuddy\skills`、`.agents\skills` 和项目内相应目录。
3. 复制工作台数据目录。打包版在 Windows 上通常为 `%APPDATA%\Skills Manager Pro`，其中包括：
   - `skill-workbench.sqlite3`：分类、标签、快照、操作历史、AI 配置和缓存。
   - `trash`：工作台回收站内容及原路径信息。
4. 将两部分备份放入同一个带日期的备份目录，并保留文件权限。

必须在应用完全退出后复制数据库，避免只复制到 WAL 事务的一部分。若目录中仍有 `skill-workbench.sqlite3-wal` 或 `skill-workbench.sqlite3-shm`，应把它们与主数据库一起复制。

## 恢复整套数据

1. 退出工作台。
2. 先把当前工作台数据目录整体另存一份，不要直接覆盖唯一副本。
3. 把备份的工作台数据目录恢复到原位置。
4. 把原 Skill 目录恢复到记录的原路径；项目盘符或目录变化时，启动后在“扫描目录”中重新添加项目根。
5. 启动工作台并执行一次“全部重新扫描”，核对 Skill 数量、只读边界、分类和历史记录。

## 仅重建索引

如果 `skill-workbench.sqlite3` 丢失，但原 Skill 文件仍在，删除或移走损坏数据库后重新启动即可重建索引。自定义分类、标签、操作历史、快照、AI 服务配置和分析缓存无法仅从 Skill 文件恢复，因此数据库仍应纳入常规备份。

## 密钥说明

AI Key 的数据库密文与当前 Windows 用户上下文绑定。把数据库复制到另一台电脑或另一个 Windows 用户后，密钥可能无法解密；此时删除旧服务配置并重新输入 Key。不要把明文 Key 放入备份说明、日志或导出文件。
